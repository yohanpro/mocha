## 한 줄 요약

백엔드 주문 무결성은 오늘 프로덕션급이 됐는데(신규 RPC), **그 앞단 주문 UI가 깨져 있어
현재 소비자는 주문을 완주할 수 없다.** 이게 실판매 오픈의 단일 최대 리스크다.

---

## 1. 스택 (검증: package.json)

- Next.js **16.2.6** / React **19.2.4** / Supabase SSR / Vercel
- 라이브: `mocha-gilt-beta.vercel.app` — 로컬 dev와 **동일한 라이브 Supabase DB**를 본다
  (검증: 로컬에서 넣은 테스트 주문이 프로덕션 상품목록 재고에 즉시 반영됨).

## 2. 데이터 (검증: schema.sql + 라이브 REST 호출)

- 테이블 4개: `products` · `orders` · `customers` · `posts`, 전부 RLS 적용.
- **재고 트리거가 라이브에 존재하고 정상 작동**한다 — 주문 insert 시 재고 1회 차감,
  주문 취소 시 재고 복구 (검증: RPC 주문 후 재고 20→19, 관리자 취소 후 19→20 복구 확인).
- 이미지: 전부 **외부 URL(Unsplash 등)**. Storage 버킷 미생성 → 실제 사진 업로드 미구현.

## 3. 주문 경로 (오늘 작업 + 검증)

### ✅ 백엔드 — `place_order` RPC 신규 (프로덕션급)
`supabase/place-order-rpc.sql` 작성 후 라이브 적용. REST 직접 호출로 3개 관문 통과:

| 검증 | 결과 |
|---|---|
| 정상 주문(qty 1) | 200, 주문 UUID 반환 — orders+customers 원자적 생성 |
| 초과주문(qty 999) | 400 `재고가 부족합니다` — 거부, 주문 안 생김 |
| 이중차감 | 재고 정확히 −1 — 트리거와 안 겹침 |
| 서버 가격계산 | 금액 미전송에도 8,000원 저장 — 클라 조작 불가 |

- `submitOrder.ts`: 2단계 insert → RPC 1회 호출로 교체, 클라 `total_price` 제거.
- `types/index.ts`: `place_order` Functions 등록. `tsc --noEmit` 통과.

### 🔴→✅ 프론트 — 주문 UI 런칭 블로커 2개 (발견 후 당일 수정·검증 완료)

| # | 버그 | 위치 | 수정 |
|---|---|---|---|
| A | "주문하기" → **404** | 상품 상세가 `/checkout`로 링크 | `products/[id]/page.tsx` 링크 `/checkout` → `/order` |
| B | 배송입력이 `<form>` 밖 (제출 필드 0개) | `OrderForm.tsx` 구조 | `<form>`이 그리드 전체를 감싸도록 재구성 |

**End-to-end 검증 완료**: 상세 "주문하기" → `/order` 진입(404 아님) → 폼 제출 시 필드
`[name,phone,address,memo]` 전송 확인 → RPC 통과 → 성공화면(주문번호 `8185DDFC`, 8,000원) →
재고 −1. **이제 고객이 실제 UI로 주문을 완주한다.**

> ⚠️ 미커밋/미배포: A·B 수정 + RPC 연동 코드(submitOrder/OrderForm/page/types)는 로컬만. main push 시 배포.
> ⚠️ 테스트 주문 2건 잔존(`A62C3192`, `8185DDFC`) — 관리자에서 취소하면 재고 18→20 복구.

### 🟡 네비게이션 이슈
- 네비 "주문 조회" → `/order` → **`/products`로 리다이렉트** (주문 조회 기능 없음, 오해 유발).
  `/order`는 사실 주문서 라우트인데 `?product=` 없이는 튕긴다.

## 4. 화면별 상태 (검증: 브라우저 실제 확인)

| 영역 | 화면 | 상태 |
|---|---|---|
| 소비자 | 홈 `/` | ✅ 렌더 정상 |
| 소비자 | 상품목록 `/products` | ✅ (재고·가격 노출) |
| 소비자 | 상품상세 `/products/[id]` | ✅ 렌더 / 🔴 주문버튼 404 |
| 소비자 | 피드 `/feed` | ✅ 렌더 정상 |
| 소비자 | 주문서 `/order?product=` | ⚠️ 렌더되나 폼 구조 깨짐(블로커 B) |
| 관리자 | 로그인 `/admin/login` | ✅ (proxy가 `/admin/*` 인증 보호) |
| 관리자 | 주문 목록·상태변경·취소 | ✅ 런타임 확인(주문 조회·8,000원 표시·상태변경·취소복구) |
| 관리자 | 상품 목록·수정 | ✅ 화면 진입 확인 |
| 관리자 | 피드 목록·새 글 | ✅ 화면 진입 확인 |

> 관리자 경로는 `app/admin/*` (라우트 그룹 아님) → URL `/admin/...`. 소비자는 `(consumer)` 그룹이라 prefix 없음.
